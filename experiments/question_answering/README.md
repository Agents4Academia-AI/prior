# Structure-seeking questions: Prior's atlas vs. a browser vs. closed book

A small, complete experiment. When a researcher asks a question whose answer *is*
a piece of graph structure — *"what actually builds on X?"*, *"do these papers
disagree?"*, *"where did this method come from?"* — does having that structure
produce a better answer than searching for it?

Three arms answer the same eight questions, blind, and an independent judge scores
them without knowing which is which:

| | |
|---|---|
| **GRAPH** | Prior's v12 atlas — 152 papers, 581 contributions, 989 typed edges — through 12 local tools. No web. |
| **WEB** | `WebSearch` + `WebFetch`. No atlas. |
| **NULL** | No tools at all. The model answering closed-book — the true baseline. |

**The result in one line:** the atlas wins 5 of the 6 structural questions and
loses both controls it was designed to lose, gaining **+2.50 groundedness over
closed-book** against the browser's **+1.83**, with **0 fabrications** in 57 named
papers. Full numbers, all 24 answers and every judge verdict: **[RESULTS.md](RESULTS.md)**.

## Try it on your own question

```bash
python ask.py "Which papers actually extend AIDE, rather than just citing it?"
```

That runs the graph arm on your question, prints the answer, and draws the
exploration figure. Four files land in `out/ask/`:

| file | what it is |
|---|---|
| `<id>.answer.md` | the answer, the papers it named, its confidence, its stated limits, and a table of every call it made |
| `<id>.svg` | the exploration figure — vector, Arial, white background, drops straight into PowerPoint |
| `<id>.md` | the call-by-call narrative including the **full justification text of every relationship it read** |
| `<id>.json` | the explored subgraph in Prior's `GlobalGraph` shape, for the app's viewer |

Useful variants:

```bash
python ask.py --dry-run "..."          # free — shows the exact prompt, calls nothing
python ask.py "..." --id aide          # choose the output filename
python ask.py "..." --arm web          # same question, browser arm (no figure)
python ask.py --replot aide --png      # redraw the figure only — free
python ask.py --replot aide --max-listed 8 --aspect 0.5 --font-scale 1.3
python ask.py --list                   # everything you have asked so far
```

**Run it in your own terminal.** It uses your Claude Code subscription through the
Agent SDK — no API key, nothing metered — but it does consume your rate window.
One question is roughly $0.25 of subscription-equivalent credit and 30–90 seconds.
Ctrl+C is safe: a partial answer is never saved, and re-asking a saved question
replays from disk for free.

The figure repays a minute of explanation — the three rings mean three different
strengths of engagement, and the difference is the point. See
**[visualisations_explained.md](visualisations_explained.md)**.

## What is in this folder

**Scripts — the pipeline, in order**

| file | costs? | what it does |
|---|---|---|
| `questions.json` | free | the 8 questions, with `family`, `expected_winner`, and the live graph structure behind each. **Never shown to any arm.** |
| `qa_arms.py` | free | the three arms: tools, prompts, the seal. `--selftest` asserts the wiring with no model call |
| `qa_gen.py` | **$** | runs the arms and writes `out/answers.jsonl` |
| `qa_judge.py` | **$** | blind 3-way judging into `out/qa_judgements.jsonl` |
| `report.py` | free | renders `RESULTS.md` from those two files |
| `trace.py` | free | replays the graph arm's logged calls and draws the figures into `out/traces/` |
| `ask.py` | **$** | ask your own question, get the answer and the figure |

**Checks — all free, all mechanical, no LLM**

| file | what it proves |
|---|---|
| `verify_named.py` | every title the graph arm named resolves to the 152-paper corpus (0 of 57 fail) |
| `check_fabrication.py` | re-examines every `fabricated` flag the judge raised against the corpus (9 raised, 9 overturned) |
| `check_leakage.py` | no answer reveals how it was produced — the blinding gate (clean on 24/24) |
| `check_docs.py` | every prompt quoted in ARMS.md and JUDGING.md still matches the code |

**Data**

| | |
|---|---|
| `out/answers.jsonl` | 24 rows — one per (question, arm), with the full answer, every tool call and its arguments, and all the metrics |
| `out/qa_judgements.jsonl` | 24 rows — one per (question, judge run) |
| `out/traces/` | the 8 exploration figures: `.svg`, `.png`, `.json`, `.md` |
| `out/ask/` | whatever you asked with `ask.py` |
| `out/failures.jsonl`, `out/dropped*.jsonl` | rows that produced no answer, and rows deliberately discarded — kept, not deleted |
| `out_v1/`, `out_v2_graph/`, `out_judge_v1/` | archived earlier runs. **`out_v1/` is not valid for scoring** — the arms were unsealed. Kept so both sides of every revision can be compared |

## Reproducing the whole thing

Everything marked **$** spends subscription credit and must run **in your own
terminal**, never spawned by an agent. All of it is checkpointed, Ctrl+C safe, and
resumes into only what is missing.

```bash
# 1. free — check the wiring and the seal before spending anything
python qa_arms.py --selftest
python qa_gen.py --dry-run

# 2. $7.20 — 8 questions x 3 arms  (~26 min)
python qa_gen.py

# 3. $4.50 — 8 questions x 3 order-swapped judge runs  (~23 min)
python qa_judge.py --repeats 3

# 4. free — the checks, then the report
python check_leakage.py
python verify_named.py
python check_fabrication.py
python report.py            # -> RESULTS.md

# 5. free — the figures
python trace.py --png       # -> out/traces/
```

Total ≈ **$11.76** and about an hour, comfortably inside one rate window.

## What this experiment does not show

Stated up front, because it is the first thing a reader should attack.

**The questions were chosen to be ones the atlas should be good at.** That is
deliberate — this is a capability demonstration on structure-seeking questions,
not an unbiased QA benchmark, and claiming otherwise would be dishonest.

What makes it more than a rigged demo is the two **control** questions the atlas
was predicted to *lose*, registered before the run and reported in the same table.
`c01` asks about AlphaFold and protein binder design — entirely outside the
corpus. `c02` asks for numbers that live in a results table the bundle does not
hold. Both went the predicted way, and on `c01` the graph arm searched, found
nothing, said so, and named no structural-biology papers. A result reading "Prior
wins 8/8" would be a rigged benchmark; "Prior wins the six structural questions
and loses both controls, exactly as predicted" is evidence about *where* the
structure helps.

Three further limits worth knowing before quoting anything:

- **Six questions is a pilot, not a study.** Graph − web is 0.67 on groundedness,
  which is below the judge's own run-to-run noise. The lift over closed-book is
  the number that survives; the win rate is not, and is deliberately absent from
  RESULTS.md.
- **Three design decisions were made after seeing results** — the tool surface
  twice, the judge rubric once. Each is defended in place and each keeps the old
  numbers alongside the new, but the pattern is part of the result.
- **The compactness prediction failed.** The graph arm reads *more* than the web
  arm, not less. Why, and what remains of the claim, is
  [ARMS.md §6](ARMS.md#6-why-the-compactness-prediction-failed).

Full list: [PLAN.md §8](PLAN.md).
